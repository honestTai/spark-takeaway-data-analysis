# 外卖数据分析系统项目分析

## 1. 项目是什么

这是一个“基于 Spark 的外卖数据分析系统”，目标是围绕外卖业务数据做以下几件事：

1. 采集数据：从美团 H5 页面爬取商户和菜品数据。
2. 导入数据：支持把商户、菜品、订单数据从 CSV/JSON 文件导入系统。
3. 清洗数据：做标准化、校验、去重、异常值处理，并支持配置清洗规则。
4. 分析数据：对商户销量、价格区间、热门菜品、用户行为、订单趋势、菜品分类等做统计分析。
5. 展示数据：前端通过图表和表格展示分析结果、概览信息和商户列表。
6. 认证访问：通过用户名密码登录，使用 JWT 做接口鉴权。

从代码结构看，这是一个“前后端分离”的项目：

- 前端：`front/`，Vue 2 + Element UI 的单页应用。
- 后端：`src/main/java/com/takeaway/analysis/`，Spring Boot + MyBatis + Spark。
- 接口前缀：后端统一挂在 `/api` 下，前端 axios 默认也请求 `/api`。

## 4. 核心业务模块

### 4.1 登录认证

作用：

- 用户通过账号密码登录。
- 登录成功后下发 JWT。
- 前端后续请求带上 `Authorization: Bearer <token>`。
- 后端拦截器校验 token，有效后把用户信息塞进 request。

怎么实现：

- 前端登录页调用 `/auth/login`。
- 后端根据用户名查 `sys_user` 表。
- 使用 `BCryptPasswordEncoder` 校验密码。
- 使用 `JwtUtil` 生成 token。
- `JwtAuthenticationInterceptor` 拦截除登录、刷新 token 之外的接口。

关键代码：

### 4.5 数据清洗

作用：

- 对商户、菜品、订单做数据质量处理。
- 规则包括评分范围、价格范围、销量范围。
- 支持前端配置清洗规则并保存到数据库。

怎么实现：

- 清洗规则保存在 `cleaning_rules` 表。
- 清洗前先读取数据库中的最新规则。
- 对数据做：
  - 标准化：trim、电话保留数字、默认值填充。
  - 校验：必填字段、范围、数值合法性。
  - 异常值处理：越界时压到边界值。
  - 去重：
    - 商户：商户名去重
    - 菜品：商户 ID + 菜品名去重
    - 订单：订单号去重
  - 数据库重复检查：
    - 商户：对已有商户名检查
    - 菜品：对 `merchantId + dishName` 检查

- 商户评分与销量关系

- 订单趋势
- 菜品类别占比

怎么实现：

- 统一通过 `AnalysisController` 暴露接口。

- 结果会先放进内存缓存，再落到 `analysis_results` 表做数据库缓存。
- 如果实时计算失败，会尝试回退到数据库缓存结果。
- 少量简单统计直接走 MySQL，不走 Spark：
  - 商户评分与销量关系
  - 商户类型对比

## 6. 各功能“是干嘛的”和“怎么实现的”

### 6.1 登录认证

是干嘛的：

- 防止未登录用户直接访问业务接口。
- 为前端页面提供登录态。

怎么实现的：

- 前端在 `front/src/utils/request.js` 中统一给请求加 token。
- 路由守卫在 `front/src/router/index.js` 中判断本地是否有 token。
- 后端拦截器 `JwtAuthenticationInterceptor` 检查 `Authorization` 请求头。
- 登录时从 `sys_user` 表取用户信息，BCrypt 校验密码，通过后生成 JWT。

### 6.2 商户/菜品爬取

是干嘛的：

- 从外卖平台补充商户、菜品主数据。

怎么实现的：

- 后端用 Selenium 模拟真实浏览器而不是只做 HTTP 抓包。
- 支持注入定位和 cookie，以便访问美团 H5 页面。
- 对商户数据：
  - 打开首页
  - 搜索关键词
  - 滚动页面
  - 解析 DOM 或脚本 JSON
  - 产出 `Merchant`
- 对菜品数据：
  - 打开商户菜单页
  - 滚动页面
  - 解析 DOM 或脚本 JSON
  - 产出 `Dish`
- 最后统一走数据清洗和数据库保存。

### 6.3 文件导入

是干嘛的：

- 用已有业务文件快速导入历史数据，而不是只能靠爬虫。

怎么实现的：

- 接口接收 `MultipartFile`。
- 根据每一行是 CSV 还是 JSON 决定解析方式。
- 商户、菜品、订单分别解析成各自实体对象。
- 调用数据清洗服务处理。
- 成功记录入业务表，失败信息写进导入日志。

### 6.4 数据清洗

是干嘛的：

- 保证进入分析模块的数据质量。
- 避免脏数据影响统计结果。

怎么实现的：

- 清洗规则保存在数据库，可以在前端调整。
- 商户清洗重点：
  - 商户名必填
  - 评分、起送价、总销量范围验证
  - 对本次数据和数据库现有数据都做去重
- 菜品清洗重点：
  - 商户 ID、菜品名、价格必填
  - 同商户下按菜名去重
- 订单清洗重点：
  - 订单号、用户 ID、商户 ID、金额合法性校验
  - 按订单号去重

### 6.5 数据分析

是干嘛的：

- 为运营、业务分析、数据展示提供图表和统计结果。

怎么实现的：

- Spark 侧通过 JDBC 直接把 MySQL 表读成 `Dataset<Row>`。
- 使用 Spark SQL / DataFrame API 做 `select`、`filter`、`groupBy`、`agg`、`orderBy`。
- 结果统一转成 `List<Map<String, Object>>` 返回给前端。
- 结果会缓存：
  - 内存缓存：减少重复计算
  - 数据库缓存：分析失败时回退

### 6.6 商户管理

是干嘛的：

- 给业务方查看当前系统里的商户数据。

怎么实现的：

- 前端传分页、筛选条件。
- 后端计算 offset。

## 9. 当前代码里的几个实际情况

这些点对理解项目很重要：

1. `系统设置` 页面目前主要是前端静态页面，没有真实后端保存逻辑。
2. `数据清洗` 页面中的“清洗统计”目前是前端静态值，没有看到真实统计接口。
3. 后端有 `/crawler/batch` 批量爬取接口，但当前前端页面没有对应入口。
4. `用户消费金额区间` 的接口有实现，但前端页面里这个 tab 被注释掉了。
5. 首页的“商户类型分布”图表代码也有一部分被注释掉。
6. 分析模块并不是全部都走 Spark，部分简单统计直接走 MySQL。
7. 爬虫模块包含“提取失败时返回模拟数据”的兜底逻辑，所以测试时可能看起来“有结果”，但不一定都是真实爬到的数据。

## 10. 总结

这个项目本质上是一个“外卖业务数据采集 + 清洗 + 存储 + 分析 + 可视化展示”的完整闭环系统。

它的技术路线很清晰：

- 前端负责页面、表格、图表和上传交互。
- Spring Boot 负责 API、业务编排、认证、导入和清洗。
- MyBatis 负责业务数据读写。
- Spark 负责分析型聚合计算。
- Selenium 负责动态页面爬取。

如果你要继续读代码，建议按这个顺序看：

1. `front/src/router/index.js`
2. `front/src/api/index.js`
3. `src/main/java/com/takeaway/analysis/controller`
4. `src/main/java/com/takeaway/analysis/service/impl`
5. `src/main/resources/mapper`

这样最容易把“页面 -> 接口 -> 服务 -> SQL”整条链串起来。
